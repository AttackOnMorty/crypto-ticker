### Bugs

#### F1 · 🟡 Medium — Malformed feed values render as `∞` / `NaN` instead of the placeholder

**Status:** 🆕 new · **Effort:** Quick win

**Impact:** A malformed or hostile Binance payload makes the menu/status bar show `+∞`, `NaN`, etc., and miscolours the change indicator — defeating the formatter's stated "never echo untrusted feed" contract.

**Fix:** Reject non-finite parsed numbers in the formatter so they return the `—` placeholder.

<details><summary>Technical details</summary>

**Where:** `PriceFormatter.swift:price`, `PriceFormatter.swift:percent`

**Evidence:** Both guard only `guard let value = Double(raw)`. Swift's `Double(_:)` parses `"inf"`, `"nan"`, `"1e400"` (→ `.infinity`). Verified output: `price("inf") = "+∞"`, `price("nan") = "NaN"`, `percent("nan") = "nan%"`. Reaches UI via `handleIncomingData` → `prices[symbol] = PriceFormatter.price(...)`. `"nan"` also flows to `percentValue` (`NaN >= 0` is false → spuriously red).

**Suggested fix:**

```swift
guard let value = Double(raw), value.isFinite else { return placeholder }
```
</details>

#### F2 · 🟡 Medium — A healthy socket can stay stuck showing "connecting" indefinitely

**Status:** 🆕 new · **Effort:** Moderate

**Impact:** On a quiet/low-liquidity pair the connection is open and healthy but the row shows the red `○` glyph and the status bar shows `⏳` until the first trade prints — the user sees a false "not connected".

**Fix:** Promote the state to `.connected` on a successful keepalive ping (or on socket-open), not only on the first received trade message.

<details><summary>Technical details</summary>

**Where:** `WebSocketManager.swift:handleReceive`

**Evidence:** The only `.connecting → .connected` transition is line 174, inside the `.success` branch, which fires only on a received *message*. Binance `@trade` pushes nothing until a trade prints. `pingActiveSockets` returns early on ping success (`guard let error else { return }`) so a healthy pong does not promote state. Consumers `isConnected(for:)` and `StatusBarText.indicator` both treat non-`.connected` as down.
</details>

#### F3 · ⚪ Low — Deselecting a symbol mid-backoff leaves stale `.error` state and a leaked attempt counter

**Status:** 🆕 new · **Effort:** Quick win

**Impact:** No crash; the symbol's `connectionStates` is stuck at `.error` and its `reconnectAttempts` never clears, so a later re-select starts backoff from an inflated attempt count (longer first reconnect delay).

**Fix:** On deselect, clear `connectionStates`/`reconnectAttempts` for the symbol even when no live socket exists (it was already removed on failure).

<details><summary>Technical details</summary>

**Where:** `WebSocketManager.swift:toggleCryptoSelection` (interaction with `handleConnectionFailure`/`scheduleReconnect`)

**Evidence:** `handleConnectionFailure` removes the task from `webSocketTasks` before the backoff sleep. If the user toggles OFF during the sleep, `symbolsToDisconnect = active.subtracting(selected)` excludes the symbol (already absent), so `disconnectWebSocket` — the only place that resets state to `.disconnected` and clears `reconnectAttempts` — never runs.
</details>

#### F4 · ⚪ Low — Negative price magnitude lands in the 4-decimal bucket

**Status:** 🆕 new · **Effort:** Quick win

**Impact:** Cosmetic only; real spot prices are non-negative so unreachable via the live feed. Shows `price` does no magnitude-based domain check.

**Fix:** Bucket on magnitude (`abs(value)`), not signed value.

<details><summary>Technical details</summary>

**Where:** `PriceFormatter.swift:price`

**Evidence:** `switch value` cases `1000...` / `1..<1000` send all negatives to `default` (4 decimals). Verified: `price("-2000") = "-2,000.0000"`.
</details>

### Performance

#### F5 · 🟡 Medium — Every trade tick rebuilds all 7 menu rows when only one changed

**Status:** 🆕 new · **Effort:** Moderate

**Impact:** While the menu is open, each trade triggers a full rebuild of all rows; ≥6/7 of the per-tick work recomputes rows whose data did not change, many times per second.

**Fix:** Carry the changed symbol on the `.priceUpdated` notification and refresh only that row.

<details><summary>Technical details</summary>

**Where:** `AppDelegate.swift:refreshMenuItems` / `configureMenuItem` (driven by `WebSocketManager.handleIncomingData`)

**Evidence:** `handleIncomingData` posts `.priceUpdated` with `object: nil` (no symbol). `dataDidChange → refreshMenuItems` iterates all 7 `availableCurrencies` and calls `configureMenuItem` (builds both plain + attributed title) on each. Bounded to menu-open + ≤7 rows.

**Suggested fix:**

```swift
// post: NotificationCenter.default.post(name: .priceUpdated, object: symbol)
// handler: refresh only the item for (notification.object as? String)
```
</details>

#### F6 · ⚪ Low — Per-row attributed-title rebuild reallocates static paragraph style, tab stops, and re-resolves the font each tick

**Status:** 🆕 new · **Effort:** Quick win

**Impact:** Multiplies redundant allocations on the (menu-open) refresh path; small per-allocation cost but fully avoidable.

**Fix:** Build the paragraph style, tab-stop array, and base-attributes dictionary once (static) and reuse.

<details><summary>Technical details</summary>

**Where:** `AppDelegate.swift:attributedMenuTitle`

**Evidence:** Each call allocates a new `NSMutableParagraphStyle`, maps 5 fresh `NSTextTab`s, looks up `NSFont(name:size:)` (uncached), and builds an `NSMutableAttributedString` — none of the style/tabs/base font depend on price data. Compounds with F5 (7 rows × N ticks/sec).
</details>

#### F7 · ⚪ Low — `connectionStateChanged` posts even when the menu is closed

**Status:** 🆕 new · **Effort:** Quick win

**Impact:** Negligible (state changes are rare), but inconsistent with the established F7-pattern that gates the price notification on `isMenuVisible`.

**Fix:** Gate the post on `isMenuVisible` for consistency, or document why it is unconditional.

<details><summary>Technical details</summary>

**Where:** `WebSocketManager.swift:updateConnectionState`

**Evidence:** Posts `.connectionStateChanged` unconditionally; `dataDidChange` already early-returns when `!isMenuVisible`, so the post is wasted work when closed.
</details>

#### F8 · ⚪ Low — Full trade payload decoded per trade to extract one field (acknowledged trade-off)

**Status:** 🆕 new · **Effort:** No code / trade-off

**Impact:** The one always-on (even menu-closed) per-trade parse cost. Negligible at ≤7 symbols; the code comment already calls it a "clarity win, not a speed one."

**Fix:** No action recommended at this scale — candidate to mark *accepted (by design)* next run.

<details><summary>Technical details</summary>

**Where:** `WebSocketManager.swift:TradeMessage.price(fromJSON:)`

**Evidence:** Per trade: `text.data(using: .utf8)` + `JSONDecoder` parses the entire Binance trade payload (ids, qty, timestamps) only to read `p`.
</details>

### Security

No findings. The realistic threat model (local plist tampering, malicious/compromised feed) is mitigated: `CryptoCurrency.validSymbols` is applied on **every** URL-construction path (REST `fetchPrice`, WS `connectWebSocket`, reconnect guarded by `shouldReconnect`); both endpoints are TLS with no ATS override or custom trust handling; untrusted feed strings are parsed defensively via `PriceFormatter` and never reach URLs or the UI raw; entitlements are minimal (sandbox + network client + user-selected read-only files).

### Maintainability

#### F9 · 🟡 Medium — Dead `plainMenuTitle` duplicates the row format and can silently drift

**Status:** 🆕 new · **Effort:** Quick win

**Impact:** A second, untested copy of the menu-row assembly that never renders (so bugs in it are invisible) yet looks authoritative — a drift trap for the next editor.

**Fix:** Drop `item.title = plainMenuTitle(...)` and the `plainMenuTitle` function; `MenuRowText.make` (tested) is the single source.

<details><summary>Technical details</summary>

**Where:** `AppDelegate.swift:configureMenuItem` (lines 117, 131–133) / `plainMenuTitle`

**Evidence:** A non-empty `attributedTitle` overrides `title` in AppKit; `item.title` is only ever written, never read (grep-confirmed). `plainMenuTitle` re-implements the row in a divergent format (`" - "`, `$…(…)`) vs the tab-delimited `MenuRowText.make`.
</details>

#### F10 · ⚪ Low — Menu debounce and tab-stop literals bypass `AppConfiguration`

**Status:** 🆕 new · **Effort:** Quick win

**Impact:** Config drift relative to the repo's "AppConfiguration is the single source of config" convention.

**Fix:** Move `menuFetchDebounce` (10s) and `menuTabStops` into `AppConfiguration`.

<details><summary>Technical details</summary>

**Where:** `AppDelegate.swift` lines 25–26 (`menuFetchDebounce = 10`, `menuTabStops = [30, 80, 180, 280, 360]`)

**Evidence:** Sibling tunables (`reconnectDelay`, `pingInterval`, `statusBarUpdateInterval`) all live in `AppConfiguration`; these two real config values (timing + layout) are hard-coded in `AppDelegate` and used at lines 233 and 137.
</details>

#### F11 · ⚪ Low — Four font constants encode two identical values

**Status:** 🆕 new · **Effort:** Quick win

**Impact:** Drift risk — change one half (`menuFont`) and forget the other (`statusBarFont`). Speculative split with no current need (YAGNI).

**Fix:** Collapse to a single `monospaceFont` / `monospaceFontSize`.

<details><summary>Technical details</summary>

**Where:** `AppConfiguration.swift:UI` lines 20–23

**Evidence:** `menuFont == statusBarFont == "Menlo"` and `menuFontSize == statusBarFontSize == 12.0`; no call site distinguishes them.
</details>
